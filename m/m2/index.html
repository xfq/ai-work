提示词核心能力

模块二 · 约2小时
学习目标：掌握结构化指令设计方法，让AI的输出更加可控、可复现。
2.1 为什么同样问AI，结果天差地别2.2 五要素：角色 + 背景 + 任务 + 要求 + 格式2.3 三种典型指令模式2.4 进阶技巧：思维链与限制性条件2.5 建立和复用你的提示词模板实践任务

2.1为什么同样问AI，结果天差地别

“帮我写一份项目延期通知”，这句话里缺了太多信息：谁发给谁？延期多久、什么原因？要不要道歉？多长？AI会用最常见、最平均的答案把空白补上，于是得到一份四平八稳、处处是【XX】、语气也不一定对的通用稿。

提示词的本质，就是把你脑子里的背景和标准显式地交代给AI。交代得越清楚，输出越可预期。

2.2五要素：角色 + 背景 + 任务 + 要求 + 格式

要素回答的问题示例
角色AI以什么身份、什么水平来做？你是一名有十年经验的项目经理，擅长与客户沟通。
背景/语境发生了什么？给谁看？已知哪些事实？A项目原定6月30日上线，因第三方接口延迟交付，需延期至7月15日。
任务具体要产出什么？请写一份发给客户方项目负责人的延期通知邮件。
要求/限制字数、语气、必须包含/禁止出现什么？300字以内；诚恳但不卑微；不要把责任全部推给第三方。
输出格式结果长什么样？按“邮件主题 / 正文 / 署名”输出。

下面这条提示词把五个要素都写全了。点击左侧的彩色标签可以“关掉”某个要素，看看少了它会出什么问题。

不必每次写满五项简单任务（如“把这段话改得更口语一点”）一两句就够。但凡是对外发送、正式留档、反复使用的任务，都值得写全。

2.3三种典型指令模式

怎么选标准清楚就用专家型；“说不清，但给你看一眼就懂”就用示范型；任何一次输出不满意，都转入迭代型，不要推倒重来。

2.4进阶技巧：思维链与限制性条件

思维链（CoT）：先分析，再输出

复杂任务直接要结果，AI容易跳步。要求它先列出分析过程，再成文，你也能顺便检查它的理解有没有偏。

在写正文之前，请先分三点列出：
1. 这封邮件的收件人最关心什么；
2. 必须传达的关键事实有哪些；
3. 哪些表述可能引起误解或不满。
确认以上分析后，再据此写出正文。

说明：一些“推理模型”会自动进行内部推理。即便如此，要求它把分析要点写出来，仍然有助于你检查思路、发现误解。

限制性条件：控制字数、语气、禁忌词与格式

控制项写法示例
字数“全文控制在300字以内”“每条要点不超过20字”
语气“诚恳、专业，不使用网络用语和感叹号”
禁忌词“不要出现‘绝对’‘保证’‘一定’等承诺性词语”
格式“用表格输出，列为：事项/负责人/截止时间”“不要使用Markdown符号”
信息边界“只使用我提供的信息；缺少的内容用【待补充】标出，不要自行编造”
最重要的一条限制“只使用我提供的信息，缺失处标注【待补充】”。它能大幅减少AI编造数据和进展，后面每个写作任务都会用到。

2.5建立和复用你的提示词模板

当一条提示词被验证好用，就把它变成模板：固定的部分（角色、要求、格式）保留，每次变化的部分换成变量。

你是一名经验丰富的行政。
请根据以下信息起草一份发给{{发送对象}}的{{通知类型}}通知：
- 事项：{{事项}}
- 时间地点：{{时间地点}}
- 需要配合的事项：{{需要配合的事项}}
要求：语言简洁规范，300字以内；只使用以上信息，缺失处标注【待补充】。
格式：标题 / 正文 / 落款与日期。

建议给每条模板附上三样东西：适用场景、使用注意、最近一次修改。针对高频任务（通知、周报、邮件、汇报）各沉淀1—2条，就够覆盖大部分日常工作。

实践任务

写一份项目延期通知：裸提示 vs 结构化提示

先用一句话的“裸提示”生成一版，再用五要素重写提示词生成第二版，对比两者的差距，并把好用的那条沉淀成你的第一条可复用模板。下面的示例展示了常见的差距，你的实际结果可能不同。

  1. 在AI工具中输入裸提示“帮我写一份项目延期通知”，保存结果。
  2. 用五要素写一条结构化提示词（可以用你真实的项目情况，但去掉敏感信息），生成第二版。
  3. 从完整性、语气得体度、可修改性三方面对比，填写下表。
  4. 把结构化提示词中会变化的内容换成 {{变量}}，形成你的第一条模板。
